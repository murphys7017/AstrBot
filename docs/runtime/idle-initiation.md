# 空闲主动接话

空闲接话复用 Personal Heartbeat → Runtime Observation → Gate → Personal Policy → Persona 的已有链路。它提供一次开启轻话题的机会，由策略判断是否表达，不保证到点必说。消息通知、邮件及跨适配器订阅不在本轮范围。

## 时机与次数

- 需启用现有心跳、空闲主动发起及相应人格策略；使用原来的空闲阈值，默认 1800 秒，不修改用户已保存的设置。
- 必须已经有真实用户互动。计时从最近用户输入与最近成功回复完成两者中较晚的时间开始；长回复和中途主动表达会推迟接话时机。
- 完成反馈优先采用对话轮次的结束时间，避免把流式回复片段的创建时间当成回复完成；既有表达冷却也使用该完成边界。
- 有排队、执行、跟进中的对话或未完成的资源清理时，不提交空闲机会，也不提前消耗这次机会。实际检查随已有心跳进行，阈值不是精确定时器。
- 每次新的用户互动最多提交一次空闲机会，沿用持久化去重。策略选择不说话、表达失败或用户没有回应，都不会让同一轮空闲不断重试；新用户互动后才有下一次机会。
- 静音、安静时段、表达冷却和每日预算继续由现有 Gate 控制。

## 过期与撤销

空闲机会自提交起有效 5 分钟，包含等待、策略请求及主动表达。较长的延后不会在几个小时后补出一句旧问候。有效期没有增加配置项。

真实用户输入绑定到当前运行时后，在等待对话执行权之前即撤销旧空闲机会，包括被任务执行器接收的补充输入。撤销信号复用已有 Observation/Policy/Action 生命周期，阻止过时请求继续输出；已发送的片段仍由原有播放打断机制处理。内部心跳和主动表达不当作新的用户输入。

## 内容

策略可以承接近期对话中的具体轻话题，也可以结合人格与已知偏好轻量分享或开启新话题，不必每次追问上一件事；尊重结束话题、忙碌和不想聊天的表达。没有适合内容可以保持安静；不把沉默解释为身体离开、孤独或低落，不反复询问“在吗”、催促回应或重复关心。该约束集中在已有 Policy 提示中，不新增模型请求或另一套回复生成链路。

## 验证与加载

这轮修改仅在 AstrBot Core，不需要重新构建 AG99live 前端。不自动开启设置或重启进程。需完整重启 AstrBot 加载修改，再通过实际空闲、用户插话及播放日志验收；合成时间的边界验证不能证明真实语音和 Live2D 行为。

验证结果：修改的 Python 文件 Ruff/编译通过；已有两项空闲接话用例通过，完成时间修正后的两项交付/冷却用例也通过。公开运行时边界确认了成功回复后的延时、忙碌不消耗机会、有效事实的五分钟期限及新输入撤销。尚未调用真实策略模型或进行语音播放验收。

提交前复核未发现新的阻断问题：内部主动表达不当作用户输入，不会撤销自身；真实输入在等待执行权前撤销旧接话，已有守卫覆盖策略和表达阶段。沿用已通过的验证结果，未重复运行未变化的测试。仅提交空闲接话相关文件，保留其他未提交工作。
