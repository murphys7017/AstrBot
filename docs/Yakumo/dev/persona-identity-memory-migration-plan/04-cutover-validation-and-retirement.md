# 切换、验收与旧路径退出计划

## 文档状态

- **状态**：设计/计划
- **所属总计划**：[人格中心化、统一身份与长期记忆架构调整总计划](00-overall-plan.md)
- **实施阶段**：Phase 4
- **风险等级**：高。涉及默认配置、实际运行和兼容路径退出。

## 1. 切换原则

切换按单一能力逐步进行：

1. 先启用统一身份观测，不改变作用域。
2. 在用户作用域模式下启用 canonical scope，限定到配置绑定的身份。
3. 再启用结构化 memory extension。
4. 确认无重复后，关闭临时消息注入。
5. 最后关闭内置长期记忆注入和不再需要的预热路径。

每一步都应有独立配置开关和可观察日志。

## 2. 配置切换顺序

### 阶段 A

- `canonical_user_id` 只记录解析结果。
- LivingMemory 继续使用旧作用域。
- Prompt 继续使用当前注入路径。

### 阶段 B

- 在用户作用域模式下为配置绑定的身份启用 canonical scope。
- 未绑定身份和其他作用域模式保持原行为。
- 观察新 scope 的写入、召回和缓存命中。

### 阶段 C

- 启用结构化 `memory` 注入。
- 保留临时消息路径作为回退。
- 通过事件级去重标记确保单次只注入一次。

### 阶段 D

- 关闭临时消息注入。
- 关闭内置长期记忆 Prompt 注入。
- 检查 AG99live 和其他插件是否仍依赖内置 Memory 预热。

## 3. 验收矩阵

### 3.1 身份

- 同一绑定用户从 QQ 和 WebChat 发送消息。
- 用户作用域模式下，两个来源产生同一个 canonical scope。
- 未绑定用户继续使用当前配置的作用域规则。
- sender name 变化不改变绑定身份。
- 群聊继续遵守当前 `memory_scope_mode`、`isolated_sessions` 和会话规则。

### 3.2 Prompt

- `turn_plan` 可以按配置看到记忆。
- `olv_stream` 可以按配置看到记忆。
- `final_result` 可以按配置看到记忆。
- `proactive` 可以按配置看到记忆。
- `progress` 默认不包含记忆。
- Core 默认不包含 Persona 记忆扩展。
- 记忆位于当前用户输入之前。
- 同一事件没有临时消息和结构化扩展双重注入。

### 3.3 LivingMemory

- 召回快照为空时 Prompt 正常生成。
- 召回异常时普通回复继续。
- 写入只在回合完成后执行。
- 用户作用域模式下的新 canonical scope 可以写入和召回。
- 旧 scope 数据仍可在原作用域中查看。
- Dashboard、归档、恢复和作用域诊断继续可用。

### 3.4 性能

- 结构化记忆注入不增加额外 LLM 请求。
- 普通回复不等待本轮记忆写入。
- 记忆召回耗时、条数和字符数可以诊断。
- Prompt 总预算不会因为记忆扩展无界增长。

## 4. 旧路径退出条件

满足以下条件后，才退出旧路径：

- 结构化路径连续通过普通对话、OLV、主动 Persona 的真实运行验证。
- 所有目标 View 的记忆可见性符合配置。
- 已确认不存在重复注入。
- 绑定身份、未绑定身份和不同 `memory_scope_mode` 的作用域行为均有记录。
- 召回失败、插件未加载和配置关闭均有明确结果。
- 旧插件和 AG99live 不再依赖内置长期记忆预热。

旧路径退出后，保留配置读取兼容和诊断，不保留默认双写或双注入。

## 5. 回滚方案

### Prompt 回滚

关闭结构化注入，恢复临时消息注入或暂时不注入长期记忆。

### 身份回滚

关闭 canonical scope，恢复切换前的 `memory_scope_mode` 和身份作用域规则。

### 插件回滚

恢复上一个 LivingMemory 插件版本，并通过部署脚本重新同步运行目录。

### 数据处理

回滚不删除 canonical scope 数据，不自动合并或反向迁移历史记录。

## 6. 发布与文档同步

完成每个阶段后：

1. 更新对应分计划的实施状态。
2. 更新 [Prompt 模块说明](../../modules/prompt.md)、[Memory 架构](../memory/architecture.md) 和当前状态文档。
3. 更新 LivingMemory 源仓库的配置与架构文档。
4. 通过源仓库提交，再执行部署脚本。
5. 在发布记录中写明是否需要重启、是否需要清理缓存以及是否有旧 scope 数据。

当前 AstrBot 的 `data/plugins` 目录属于运行时部署副本，不能作为 LivingMemory 或 AG99live 的源代码修改位置。
