# AG99 桌面主应用与 AG99live 身体接入计划

> **状态：方向已确认，实施计划草案。**
>
> 本计划建立在两个已确认的产品决定上：AG99 以桌面体验为中心；AG99live 是 AG99 的身体运行时。AG99 桌面端只提供统一入口并连接已经运行的服务，不启动、托管、打包或替代这些服务。

## 1. 目标形态

```text
AG99 Desktop Shell
  ├─ 连接已经运行的 AG99 Agent Platform
  └─ 连接已经运行的 AG99live Body

AG99 Agent Platform
  ├─ Persona / 会话 / Memory / 主动行为
  ├─ Provider / Tools / Plugins
  └─ Desktop Body Output 调度

AG99live Body
  ├─ 本地感知与即时反应
  ├─ Live2D / 音频 / 动作 / 表情
  └─ 设备与桌面状态
```

AG99 Desktop Shell 是用户入口和控制面，不是新的 Agent Runtime，也不是进程管理器。AG99 和 AG99live 可以在本机或其他可访问主机上独立运行；桌面端只负责连接、认证、展示状态、发送用户操作和呈现结果。

## 2. 已确认的边界

### AG99 Desktop Shell 负责

- 统一登录、连接和服务状态入口；
- 选择或切换 AG99 服务端点和 AG99live 身体端点；
- 展示 Persona、会话、记忆、主动行为、工具和身体状态；
- 将用户操作路由给已有服务；
- 提供断线、重连、权限失败和服务不可用的可理解反馈。

### AG99 Desktop Shell 不负责

- 启动或停止 AG99 Agent Platform；
- 启动或停止 AG99live Body；
- 在桌面端复制 Persona、Memory、Provider、主动策略或播放时钟；
- 直接替代 AG99live 的 Live2D、音频和设备执行逻辑；
- 因为“桌面应用”定位而要求仓库合并或进程合并。

### 服务端负责

- AG99 负责语义决策、人格、会话、记忆、主动行为、Provider、工具和插件生命周期；
- AG99live 负责本地身体状态、即时反射、Live2D 表现、音频播放和设备生命周期；
- Adapter 负责两者之间的协议、认证边界、能力声明、消息身份和错误语义。

## 3. 实施阶段

### Phase 0：固定产品入口

交付：

- 桌面主应用的用户旅程：连接服务、选择 Persona、开始对话、查看身体状态、处理断连；
- 服务端点、身体端点、认证和权限的术语；
- “连接已运行服务”作为安装与运行假设。

验收：用户能理解 AG99 Desktop Shell、AG99 Agent Platform 和 AG99live Body 的区别。

### Phase 1：服务连接契约

先定义最小连接协议，不先做业务迁移：

- 健康检查和版本；
- 服务身份与能力清单；
- 认证失败、协议不兼容和连接超时；
- AG99 与 AG99live 的连接关系和当前实例标识；
- 本机端点配置，远端端点作为后续可选拓扑。

验收：桌面端能够判断“未配置、连接中、已连接、认证失败、协议不兼容、服务离线”六类状态。

### Phase 2：只读统一入口

先接入已有 API 和状态，不复制运行时：

- 当前 Persona、会话和连接状态；
- AG99 运行时诊断和主动行为开关；
- AG99live 身体在线状态、模型和播放状态；
- 已启用能力及缺少的配置。

验收：桌面端能从一个入口判断角色为什么没有反应，以及下一步应连接、配置还是恢复服务。

### Phase 3：统一交互入口

- 对话输入和会话切换进入 AG99 现有链路；
- Memory 查看、修改和删除继续调用 AG99 现有能力；
- 主动行为设置继续调用 AG99 Personal Runtime；
- AG99live 只接收身体表现和本地控制，不建立第二套对话入口。

验收：普通对话、会话切换、记忆操作和主动行为设置都能追溯到唯一服务 owner。

### Phase 4：身体绑定与输出闭环

- 绑定一个 AG99live Body 实例；
- 展示 Body Expression、播放、打断和终态；
- 建立 AG99 输出到身体呈现的纵向验收；
- 定义本地即时反应、输出准入和 AG99 语义主动策略的边界。

验收：主动输出能到达身体并正确播放、打断和恢复；桌面端不伪造播放成功。

### Phase 5：场景事实与身体能力扩展

在前面的链路稳定后，再设计低频、授权的桌面事实：

- 用户回来、触摸宠物、桌面忙闲等事件；
- AG99live 本地去抖、合并和权限控制；
- Adapter 到 AG99 Observation 的最小接线；
- 触摸互动、场景模式和本地输出准入。

高频鼠标、视线、Physics 和帧级状态继续留在 AG99live，不直接触发模型请求。

### Phase 6：插件化与重构

只有在真实调用方稳定后，才把连接、Body、场景和能力边界整理成插件契约。每个插件能力必须有身份、版本、依赖、权限、生命周期、失败语义和诊断；不提前复制 AG99 的 PluginManager、Provider Manager 或主动调度器。

## 4. 当前不做

- 桌面端一键启动或托管 AG99、AG99live；
- 把 AG99live 合并进 AG99 主进程；
- 先做远端服务自动发现、跨设备编排或多身体同步；
- 直播互动编排和音乐节目单；
- 在 AG99live 新建平行 Memory 或主动对话系统；
- 在连接契约稳定前进行大规模目录重构。

## 5. 关键验收顺序

```text
连接状态可解释
  -> 只读状态统一
  -> 普通对话和会话统一
  -> 身体输出闭环
  -> 主动行为与身体准入
  -> 低频场景事实
  -> 插件化与重构
```

任何阶段都以真实 AG99 + AG99live 联调为最终证据；静态类型检查和单元测试只能证明局部边界。
