迁移收益主要是降低后续吸收官方更新的改写成本、明确 HTTP 与业务逻辑边界、建立可检查的 API 契约。没有测量证据证明 Quart 是当前性能瓶颈，不以性能提升作为验收承诺。

## 2. 目标结构

```text
现有自定义 WebUI / 外部 API 客户端 / 插件页面
  -> FastAPI API 路由
       -> 明确的鉴权依赖、参数解析、响应与流式适配
       -> Dashboard Service
            -> 现有 CoreLifecycle / Manager / 数据库

旧 Quart 插件 Web Handler
  -> 有界的兼容入口
       -> 现有插件注册表、归属和卸载机制
```

目标只调整 Web 接口层及其业务装配，不重写 Personal、Persona、Core、Prompt、Memory 或 OLV 的执行语义。HTTP 请求只进入已有业务入口，不因为 FastAPI 自带生命周期而重复启动 Core、加载插件或初始化调度器。

- `api/`：路由、鉴权依赖、参数与响应适配；不直接复制一份业务流程。
- `services/`：沿用官方的功能域划分，把本地行为搬入对应服务；同一操作的旧、新路由共用一个服务。
- `schemas.py`、`responses.py`：描述新接口契约；旧接口保留原有解析和响应兼容边界。
- `asgi_runtime.py`、必要的 `astrbot/api/web.py`：只承担 Web 兼容与插件 Web API，不把框架上下文扩散进核心业务。
- `server.py`：装配、鉴权边界、静态资源和服务启动；保留现有 `AstrBotDashboard` 的调用契约及关闭信号。

Hypercorn 是否继续使用按实际装配验证决定；迁移 FastAPI 不等于必须同时换 Uvicorn。前端布局和 API 客户端迁移分开，不全量覆盖官方前端。

## 3. 必须保留的边界

1. 现有 `/api/*` 和外部 `/api/v1/*` 的地址、方法、参数别名、返回格式、会话隔离及鉴权能力不得无说明回归。
2. 官方新增接口不能仅按 `/api/v1` 前缀放行；每条受保护路由必须有已验证的鉴权依赖。现有外部 API 也不能因为复用官方通用鉴权而意外扩大 Dashboard JWT 的访问范围。
3. Profile 独立配置、全局 Provider/Adapter 资源归属、Adapter binding、Memory 配置失效处理及 SubAgent Profile reload 保持原语义。
4. 保留插件 Web API 的动态参数匹配、显式 owner、禁用/卸载/重载时的清理。系统扩展功能不重新归类为安装插件。
5. 插件 Pages 保留 sandbox、路径校验、受限资源令牌、Bridge SDK 和主题/语言同步；不能靠放宽隔离解决兼容问题。
6. SSE 与 WebSocket 保留增量交付、取消和断连清理；不能把流式响应读完后再返回。
7. 平台 webhook 保留原始正文、平台校验、明文响应和状态码；不能统一包进 Dashboard JSON。
8. 保留部署、静态资源路径优先级、桌面托管重启限制和更新保护。此次不执行数据迁移或重置。

## 4. 实施顺序

阶段状态均为待实施。顺序是迁移依赖顺序，不表示现在已经能够启动 FastAPI。

| 阶段 | 做什么 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0：冻结契约 | 固定实施基线，补齐逐接口清单、调用方和鉴权矩阵；记录真实启动与主要链路基线 | 已有修改归属明确，旧服务主链能验证，差异项有明确处置 |
| P1：基础装配 | 增加目标 ASGI app factory、公共响应和鉴权；先迁移版本/状态等简单读取接口及其服务 | 受保护接口拒绝无凭据访问，已确认的公开接口保持可用，合法登录/外部 Key 能访问各自允许接口，不重复创建 Core |
| P2：配置与管理 | 提取配置、Profile、Provider、Adapter、Persona、会话、Cron、SubAgent、知识库管理业务 | 非默认 Profile 与默认 Profile 隔离，现有自定义页面仍可读写，旧请求/响应保持兼容 |
| P3：插件与能力 | 迁移插件管理、插件 API、Pages、命令、Tools/MCP、Skills 和 Neo Skills | 旧插件请求上下文可用；重载不残留 API；内嵌页面可打开，多页面与资源权限正确 |
| P4：高风险链路 | 迁移聊天/LiveChat/OpenAPI、日志流、文件/备份、更新/T2I、webhook 与独立平台 Web 服务 | 真正增量发送、断连清理、文件边界、平台原始响应和运行时输出语义均通过验收 |
| P5：切换与收尾 | 切换生产入口为 FastAPI，移除已替代的内部 Quart 路由与重复装配，更新文档和吸收记录 | 单一业务所有者、单一运行入口；真实验收及回退准备完成；没有把待验证写成完成 |

鉴权方案在 P0/P1 先确定并验证，不留到最后补救。高风险流式、写入和生命周期的完整验收仍在对应阶段执行。

实施期间保持当前服务入口不变，按功能域准备目标路由；正式切换前目标后台必须具备完整主链。服务提取可先由旧路由调用，避免两份业务实现长期并存。新 app 的验证入口不得对同一生产数据并行执行重载、配置修改、备份恢复或平台回调；临时启动仅限隔离测试数据与测试平台。

每个实施批次只搬一个有明确验收边界的功能域。提交须另获明确指令；如获准按批次提交，每批次先审阅和验证，再提交，不按文件机械拆分不可运行的变更。

## 5. 本次不做

- 不全量合并官方 Core 或替换自定义 WebUI。
- 不同时重新设计页面分区、升级所有前端 API 调用、刷新全部依赖或机械同步官方版本号。
- 不一次性删除 Quart：旧插件及尚未迁移的独立平台服务可能仍依赖它。
- 不引入长期双后台、失败自动回落到旧框架、两份 Manager 或新数据模型。
- 不宣称插件 API、流式输出或运行副本已经验证兼容。
