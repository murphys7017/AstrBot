# 验收与切换条件

本文件描述未来迁移的验收，不是已通过测试的报告。阶段定义见 [总纲](./README.md)，接口映射见 [差异表](./01-interface-inventory.md)。

## 1. 验证原则

- 先验证公开输入输出，再验证真实前端与平台链路；检查没有异常不能替代业务验收。
- 优先复用已有测试，只运行本批次影响的最小集合。框架变化后调整 fixture，不保留只验证旧框架内部细节的过渡测试。
- 必要的新测试只覆盖关键公开边界，不增加私有方法、调用次数或大规模 mock 编排测试。
- 一个普通 HTTP 成功响应不能证明 SSE、WebSocket 或插件上传兼容。流式检查必须观察首个事件在流结束前到达。
- 把单元/边界测试、真实服务启动、浏览器和平台验收分开记录；未做项目写“未验证”，不能合并成“通过”。
- 所有可写操作使用测试 Profile、测试插件或隔离数据副本。备份恢复、更新、密码修改和生产重启不作为自动 smoke 的副作用。

## 2. 验收矩阵

| 边界 | 最小公开验收 | 不通过时的处理 |
| --- | --- | --- |
| 启动/关闭 | 隔离数据启动后实际监听测试端口；版本接口可访问；关闭后端口释放、无残留监听任务 | 修复装配/关闭信号，不靠换端口隐藏残留 |
| 管理鉴权 | 受保护接口拒绝无凭据访问；已确认的公开接口保持可用；合法登录与 Cookie 可访问管理接口；退出清除 Cookie，客户端不再携带凭据时不能访问受保护接口；过期/错误 JWT 不获得身份 | 禁止生产切换；当前 logout 不吊销已签发 JWT，不能要求迁移顺带增加吊销机制 |
| 外部 API Key | 合法 Key 只访问授权 scope；吊销后拒绝；旧载体与旧接口保持约定；请求用户名/会话归属正确 | 明确兼容与权限收紧差异，不能放宽鉴权兜底 |
| v1 边界 | 新 Dashboard v1 与旧外部 v1 都有明确鉴权；资源令牌不能访问管理接口；相似前缀不误分类 | 检查依赖及路由匹配，不用全局免鉴权 |
| 配置/Profile | 测试非默认 Profile 的读写/路由/SubAgent reload 不污染默认 Profile；Provider/Adapter 仍由全局资源所有者保存 | 回到服务所有者处修复，不复制配置制造表面隔离 |
| 本地管理接口 | `/api/stat/personal-runtime`、`/api/plugin/capabilities` 返回前端所需结构 | 补齐本地路由和服务，不能以官方缺少该功能为由删除 |
| 插件 API | 旧 JSON/动态参数 Handler 可调用；上传/响应头保持正确；卸载后旧 Handler 不再可调用，重载后无重复项 | 修复注册表分发/owner 清理，不能保留两套 Handler |
| 插件 Pages | 卡片/侧栏/详情页可进入，多页面可选；静态资源、API、上传下载、SSE、主题/语言可用；禁用及跨页访问被拒绝 | 分清路由、Bridge、资源令牌和布局的问题，不放松 sandbox |
| Pages 长时间停留 | 至少等待资源令牌 TTL 后触发真实懒加载；观察重载和令牌更新行为 | 据真实结果决定续签/刷新方案，不直接延长为无限期 |
| 原生与旧插件 SSE | 首个事件在生产者结束前到达，后续事件增量到达；客户端断开后订阅/任务释放 | 不采用 `get_data()` 缓冲作为流式兼容 |
| WebSocket/LiveChat | 合法握手、非法身份拒绝、消息/音频收发、打断和断连；三条旧 WS 地址继续可用 | 原生 WS 适配并保留旧协议，不套用普通 HTTP 兼容 |
| Personal/Core/输出 | 普通消息和工具任务走既有 Personal/Core；可见历史不混入 Ledger；全部物理发送成功后才完成逻辑消息，OLV 分段无重复/延迟回归 | 禁止绕过运行时发送消息；定位传输变化是否影响原语义 |
| 平台 webhook | GET 校验保留明文、Content-Type 和状态码；POST 原始正文/签名不变，验证无签名或错误签名仍被拒绝 | 按平台适配，不统一 JSON 包装或重新序列化签名正文 |
| 文件/备份 | 小文件上传下载内容一致；大小限制和路径越界被拒绝；分块完成/取消正确；文件令牌不能访问其他资源 | 修复入口限制及落盘/清理，真实大文件验收单独执行 |
| Skills/Tools/Neo | 插件 Skill 受原权限限制；MCP 和 Neo 管理的已有公开动作保持有效，不复制运行时 | 保留本地能力所有者，不把系统扩展重新当插件 |
| 更新/重启/T2I | 不执行生产升级；检查桌面托管保护、受控失败信息、测试模板变更与配置同步 | 在隔离副本验收，不能为了测试关掉保护 |
| 自定义前端/静态资源 | 主要管理页面读写无回归；深链刷新可用；插件页桌面/移动端无遮挡、无意外双重滚动；不存在的 API 不返回 HTML | 配套修复路由/静态规则，不覆盖自定义 UI |

## 4. 正式切换条件

1. P0 的逐接口签收表覆盖现有调用方，没有未处置的公开接口差异。
2. 受保护接口均有鉴权，旧外部 Key scope、会话归属和 Pages 资源范围通过验证。
3. 单个 CoreLifecycle/Manager/插件注册表被新后台复用；启动、关闭和重载无重复任务或残留。
4. 普通聊天、工具任务、SSE、WS、插件页面和实际使用的平台回调完成真实验收。
5. 配置、数据库和插件数据保持兼容；没有在迁移中混入无关数据变更。
6. 自定义 WebUI 与旧 API 客户端可用，更新/桌面托管保护仍生效。
7. 已准备代码、依赖环境、前端产物与数据的匹配回退点；用户明确同意切换和重启。

## 5. 回退准备

切换前记录当前运行副本、源码 commit、依赖环境、前端产物、配置和数据库备份；备份文件不提交仓库。旧运行副本和目标副本不并发写同一生产数据。

回退是受控的部署切回，不是在请求失败时自动换框架。若目标版本已经写入数据，先评估数据兼容，不盲目恢复旧备份覆盖新数据；涉及恢复、删除或重启再次取得明确指令。不得使用 `git reset --hard` 或撤销工作区其他人的修改作为回退方案。
